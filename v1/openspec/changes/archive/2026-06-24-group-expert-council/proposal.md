## Why

当前 MeClaw 有两套思考能力但彼此割裂：单 AI 的「专家模式」（一个模型演三幕：解构→发散→收敛）和「群聊」（多个真实 Bot 自由 @ 接话）。单 AI 专家模式会自我锚定、缺乏证伪与多视角；群聊接话是概率自由聊天，没有结构化认知流程。参考《多 Agent 专家组协作协议（认知议会模型）》，把群聊里的多个 Bot 编排成一支按回合制协作的专家组，能产出比单模型更可靠、可审计的决策——这是单 AI 专家模式做不到的（无法反锚定、无红队）。

## What Changes

- 新增**群聊专家会议模式（认知议会）**：在已有群聊会话上，针对一个用户议题，编排成员 Bot 走「独立诊断 → 交叉澄清 → 红队攻击 → 架构师整合」的回合制流水线，而非自由接话。
- 引入**共享黑板（Shared Blackboard）**：结构化记录 `当前共识 / 待决分歧 / 已证伪假设 / 关键约束 / 版本号`，每轮更新并作为后续轮次的唯一上下文来源（而非全文历史），控制 token。
- 引入**反锚定**：Round 1 各专家 Bot 独立产出，互相不可见；Round 2 方案匿名化后只准提澄清性问题。
- 引入**红队 / 架构师角色**：可指定成员承担红队（证伪）与架构师（强制取舍、单选推荐）职责；缺角色时由系统用临时 persona 兜底。
- **置信度标记**：每个 Bot 每轮输出附 `置信度 / 依据类型`。
- **人类仲裁停靠点**：架构师给出混合方案后暂停，等用户选定方向再进入执行细化（可选轮）。
- **入口与展示**：群聊工具区新增「专家会议」开关；前端按回合分组展示各 Bot 发言、黑板快照与最终推荐，复用现有思考/气泡渲染。
- **会议产出落库**：会议结束生成共识快照写入群记忆（`groups/{id}/memory/`），可被后续检索。
- 复用并校正单 AI 专家模式的草稿纸思路：黑板采用「冻结 + 追加」而非整块覆盖，避免早期信息被改写丢失。

## Capabilities

### New Capabilities
- `group-expert-council`: 群聊场景下的回合制多 Agent 专家会议编排——角色分配、回合流水线、反锚定可见性规则、红队/架构师机制、人类仲裁停靠点与会议产出落库。
- `shared-blackboard`: 跨轮共享的结构化工作记忆（共识/分歧/证伪/约束/版本号）的数据结构、更新规则与作为轮次上下文的注入纪律。

### Modified Capabilities
- `group-chat`: 群聊新增「专家会议」运行模式，与现有「自由接话」并存；会议进行中暂停概率接话链与自动 @ 补全。
- `group-auto-interaction`: 会议模式下接话链 / 自动 @ 概率逻辑被回合制编排接管，需明确二者互斥与切换规则。

## Impact

- 后端：新增 `backend/expert_council.py`（会议编排 + 黑板）；`backend/group_mentions.py`、`backend/groups.py`（会议 meta 字段、与接话链互斥）；`backend/api.py` / `backend/main.py`（会议会话路由、逐轮推送、产出落库）；`backend/expert_mode.py`（抽出可复用的单轮调用与黑板/草稿纸工具）。
- 前端：`web/js/group.js`、`web/js/chat.js`、`web/js/composer.js`（会议开关与逐轮渲染）、`web/style.css`、`web/index.html`。
- 记忆：会议共识快照写入 `groups/{id}/memory/entries/`，复用现有 store/indexer。
- 文档：`docs/系统结构.md`、`docs/API参考.md` 增补会议模式；新增 OpenSpec specs。
- 约束：单次会议 API 调用次数随成员数与轮数增长，需设上限与上下文压缩，避免 token 失控。
