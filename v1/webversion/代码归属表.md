# Web 版代码归属表

> 照着勾。✅ = 第几阶段要做。❌ = Web 版第一版跳过。

**图例**

- **复用** = 不用写新逻辑，HTTP 壳直接调 `backend/` 现有方法

## 五、流式事件（WebSocket 推送）

桌面版 `evaluate_js` 调用的前端函数，Web 版用 WebSocket 原样转发：

| 事件名 | 触发场景 | 前端处理函数 |
|--------|---------|-------------|
| `onToken` | 正文流式 | `chat.js` 已有 |
| `onReasoningToken` | 思考流式 | `chat.js` 已有 |
| `onStreamDone` | 生成结束 | `chat.js` 已有 |
| `onError` | 出错 | `chat.js` 已有 |
| `onLog` | API 日志 | `bot.js` |
| `onWebSearchStatus` | 联网状态 | `chat.js` |
| `onWebSearchStep` | 联网步骤 | `chat.js` |
| `onExpertStageToken` | 专家模式 | `chat.js` |
| `onCouncilToken` | 专家会议 | `chat.js` |
| `onCompressProgress` | 压缩进度 | `app.js` |

**新建文件**：`webversion/server/stream.py` 统一发这些事件。

## 六、依赖追加（写入 requirements 时）

Web 版在现有 `requirements.txt` 基础上追加：

```
fastapi>=0.110
uvicorn[standard]>=0.27
websockets>=12.0
```

可以加一个 `webversion/requirements-web.txt`，避免和桌面版混在一起。
