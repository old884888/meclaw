# MeClaw 记忆系统 — 使用帮助

> 面向日常使用。技术细节见 [记忆系统技术文档.md](./记忆系统技术文档.md)。  
> **当前状态：已实现**（设置 → 记忆 可开关；压缩时写 `entries/`；状态面板可管理；消息可「收藏」）。

## 一句话理解

记忆按**类别放进不同文件夹**，聊天时由程序**搜索相关几条**放进上下文——不是每次把整本笔记念给 AI。  
你点 **压缩上下文** 时，除了会话摘要，还会**顺便整理记忆**，重要的还会自动写进 `memory.md`。

---

## 文件夹长什么样？

每个 Bot 有自己的灵魂目录，记忆在里面的 `memory/` 子文件夹：

```text
souls/我的小助手/
  soul.md              ← 人设（你写的）
  memory.md            ← 少量核心事实（可手改，压缩时也会自动补精华）
  knowledge/           ← 固定知识手册（每次都会带上全文）
  memory/
    index.sqlite       ← 搜索索引（程序用，一般不用手改）
    entries/           ← 主格式：每条一个 Markdown（压缩时自动写）
    items/
      quote/           ← 好词好句收藏（压缩琐碎档也可能写几条）
      fact/ …          ← 遗留 JSON 条目（旧数据，新压缩走 entries/）
    docs/
      某篇文章/
        meta.json      ← 标题、标签、摘要
        chunk-001.md   ← 文章切片（很长也不会一次全塞进聊天）
        chunk-002.md
```

你可以用资源管理器打开 `entries/` 看 AI 记住了什么——**比黑盒数据库好懂**。状态面板「记忆库」也能浏览删除。

---

## 三种「记住」分别是什么？

| 类型 | 在哪 | 聊天时怎么用 | 你怎么维护 |
|------|------|--------------|------------|
| **核心事实** | 根目录 `memory.md` | 每次对话开始会带上（很少） | 手改 + **压缩时自动合并** + AI 可写 |
| **中期记忆** | `memory/entries/`（主）+ `items/`（遗留/quote） | 只搜**相关的几条** | **压缩上下文时自动写 entries/**；短句可收藏到 quote |
| **长文收藏** | `memory/docs/某篇/` | 只有你问风格/参考时才抽几段 | 点「收藏」 |

**当前聊天内容**：照旧靠聊天记录 + 压缩出来的**会话摘要**，不用你管。

---

## 压缩上下文 — 你会最常用的操作

点 **压缩上下文** 后会发生两件事：

```text
① 会话摘要  → 让当前对话还能接着聊（和以前一样）
② 记忆整理  → 把值得长期记的写进 memory/entries/…
              → 在 memory.md 追加一行索引（链到对应条目）
```

### 摘要详略（四档）

压缩弹窗里可选 **摘要详略**（不是「压得越狠」，而是**留多少细节**）：

| 档位 | 适合 |
|------|------|
| **极简** | 最省 token，只要几条要点 |
| **标准** | 日常默认 |
| **详尽** | 结构化：背景 / 要点 / 结论 / 待定 |
| **琐碎 max** | 怕漏细节、想保留更多要点和少量原话；摘要更长，占上下文更多 |

还可填 **压缩方向**（例如「保留 API 讨论，丢掉 UI」），与档位叠加。

- **设置 → 记忆**：可设「默认摘要详略」（给**自动压缩**用）
- **编辑 Bot**：可「跟随全局」或单独设默认档位
- **琐碎 max** 且开启记忆写入时，可能额外摘录最多 3 条金句到 `items/quote/`

**和 entries 的分工**：详尽的要点主要在**会话摘要**里；`entries/` 是结构化长期记忆。好句、长文请用 **⭐ 收藏**。

所以你**不用**主要靠手改 `memory.md`——压缩时系统会「顺便来一下」。  
手改仍然可以，适合你自己确定的核心设定。

**不会记的**：天气闲聊、一次性提问、联网搜到的网页（除非你明确说「记住」）。

## 正常聊天时程序在干什么？

```text
你发一句话
    → 程序在 index.sqlite 里搜索相关记忆（不是打开整个文件夹）
    → 找出最相关的几条，塞进本轮上下文
    → AI 回复
```

你看不到全部记忆列表，也**不会**每次带上所有收藏文章——这样省 token。

## 开关（设置 → 记忆）

| 开关 | 效果 |
|------|------|
| **启用记忆** | 关 = 完全不读不写 |
| **仅检索** | 聊天会用已有记忆，但压缩时**不往文件夹里写新的** |
| **记忆 token 预算** | 每轮最多用多少「相关记忆」；越小越省 |
| **自动压缩上下文** | 发消息前达到阈值时自动压缩并整理记忆 |
| **自动压缩阈值** | 滑块 50–98%（默认 85%） |
| **默认摘要详略** | 自动压缩用的档位（手动压缩可在弹窗临时改） |

**手动压缩**：侧边栏 → **状态** → 底部「压缩上下文」按钮（可选摘要详略 + 压缩方向）。

**每 Bot 覆盖**：编辑机器人 →「记忆」→ 读写 / 自动压缩可分别跟随全局或自定义。

**管理记忆**：侧边栏 → **状态** → **记忆库**（查看、删除、📂 打开文件夹）。

建议：先开「启用 + 仅检索」试几天，再放开写入。

---

## 收藏长文和好句

- **好句** → 进 `memory/items/quote/`  
- **整篇文章** → 进 `memory/docs/某篇/`，切成多块  
- **不会**把长文贴进 `memory.md`

要让 AI 参考收藏写东西，说清楚即可：

- 「按我喜欢的风格写」
- 「参考我收藏的那篇」

---

## 和 `knowledge/` 的区别

| | `knowledge/` | `memory/` |
|--|--------------|-----------|
| 性质 | 你事先准备的说明书 | 聊天里慢慢积累的 |
| 用法 | 每次**全文**加载 | **按问题搜索**几条 |
| 例子 | 产品 API 文档 | 「用户讨厌冗长回复」 |

同一段长文不要两边都放。

## 常见问题

### Q：`memory.md` 要我自己一直改吗？

**不用。** 压缩上下文时会自动把最重要的事实合并进去。你只需偶尔检查、删掉不对的，或手加 2–3 条铁定规则。

### Q：记忆存在哪？能备份吗？

整个 `souls/你的bot/` 文件夹拷走即可，包含 `memory/` 里所有分类和 `memory.md`。

### Q：记错了怎么办？

- 状态面板「记忆库」删除条目，或手删 `memory/entries/某条.md`  
- 改或删 `memory.md` 里对应索引行  
- 或先开「仅检索」防止继续写错  

### Q：和 mem-llm 一样吗？

不一样。记忆在你电脑的文件夹 + 索引里，模型仍走你配置的 API，不需要 Ollama。

## 推荐上手流程（功能上线后）

1. 给 Bot 配好 `soul_folder`  
2. 可选：在 `memory.md` 手写 2–3 条铁律  
3. 设置里开记忆，先勾 **仅检索**  
4. 聊几轮 → **压缩上下文** → 打开 `memory/entries/` 看记了什么  
5. 好段落 → **收藏**  
6. 写作时说「参考我收藏的风格」

## 群聊记忆（与私聊隔离）

- **私聊**：记忆在 `souls/{bot-id}/memory/`，该 Bot 的所有私聊对话栏共享检索。
- **群聊**：记忆在 `groups/{群-id}/memory/`，仅在该群的对话栏内检索；**不会**自动写入各 Bot 私聊库。
- 群聊中需 **@ 指定成员** 才会回复；未 @ 的消息会保存，但无 Bot 应答。
- 在私聊里问「你记得什么」只搜该 Bot 私聊记忆，不含群聊内容。

### 群 Bot 自动接话（可选）

在群设置中可开启 **Bot 自动接话**：

| 设置 | 含义 |
|------|------|
| 总开关 | 关闭时 Bot 正文里的 @ 仅展示，不触发接话 |
| 被 @ 时接话（每成员） | 关闭后该 Bot 被正文 @ 也不会回应（@ 标签仍显示） |
| 主动 @%（每成员） | 该 Bot 发言时若没写 @，按概率自动补一条 @ |
| 正文 @ 成员名 | 总开关开启且成员允许接话时，写出 @ 将触发该成员回应 |
| 接话链上限 | 单次用户消息后，Bot 互聊最多几轮（防刷屏） |
| Bot 互聊用快速模式 | 接话（Bot→Bot）时关闭思考，省 token、更快 |
| 历史上限 | 发送给模型的历史最多多少条（0=不限），控制长群成本 |

- **用户 @ Bot**：始终 100% 回复（不受成员接话开关影响）。
- **多 Bot 区分**：发给模型时，其他成员的发言会以 `[名字]:` 作为对方话语注入，当前发言者只把自己的历史视为「我」，提升人设一致性、减少串人设。
- **空回复保护**：若某成员本轮只产出思考、正文为空，会先以**快速模式自动重试一次**；仍无正文则跳过、中断接话链，不留空气泡。
- **群自动压缩**：可在群设置开启；达阈值后将旧消息摘要化（群聊保留最近 6 条），写入群级 `summary` 与群记忆库，并同步前端历史，避免长群只截断、早期信息全丢。
- **@用户**：纯装饰，不触发 API。
- 多 Bot 被 @ 时 **串行** 回复，一条接一条。

群记忆目录可在后续版本从状态面板打开（当前为 `groups/{群-id}/` 文件夹）。
