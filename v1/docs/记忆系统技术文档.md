# MeClaw 记忆系统 — 技术文档

> 对应 OpenSpec：`openspec/specs/memory-entry/`、`openspec/specs/bot-memory/`  
> 状态：**已实现**（`backend/memory/` + 状态面板 `web/js/memory.js`）

## 1. 设计目标

在**不替换**现有聊天主链路的前提下，为每个 Bot（及群聊）建立可开关、可检索、token 可控的持久记忆。

核心原则：

- **按内容分类存文件夹** — 人类可读、可备份、可手改
- **工具程序负责搜索** — 发消息前 `search_memory()` 查索引，**绝不**把整个 `memory/` 目录塞进 prompt
- **文件夹 + sqlite 双写** — 文件是真源，`index.sqlite` 是 FTS 搜索加速层
- **三层分工** — 不另建短期缓存（已有 `history` + `current_summary` + `summaries/`）
- **压缩时顺便整理** — 写 `entries/` Markdown 条目 + 自动更新 `memory.md` 索引行

---

## 2. 三层记忆模型

```text
┌─────────────────────────────────────────────────────────────┐
│ 层 1：稳定事实（启动时注入，体积小）                            │
│   soul.md          身份、语气（人工）                          │
│   memory.md        极少长期事实 + entries 索引行               │
├─────────────────────────────────────────────────────────────┤
│ 层 2：中期可检索记忆（发消息前 search_memory top-k）            │
│   memory/entries/{date}-{slug}.md   ← 主格式（YAML + 摘要/要点）│
│   memory/items/{type}/*.json        ← 遗留 + quote 收藏       │
├─────────────────────────────────────────────────────────────┤
│ 层 3：长文收藏（不默认注入，意图命中才检索 chunk）               │
│   memory/docs/{slug}/meta.json + chunk-*.md                   │
│   与 knowledge/*.md 分离                                       │
└─────────────────────────────────────────────────────────────┘

短期上下文（已有）：
  current_messages + current_summary + history/summaries/
```

## 3. 目录结构

```text
souls/{bot-id}/
  soul.md
  constraints.md                 # 可选
  memory.md                      # 层 1，灵魂根目录
  knowledge/                     # 静态知识，每次全量加载
  memory/
    index.sqlite                 # FTS 索引（搜索用，不必手改）
    scratchpad.md                # 专家模式草稿纸（非记忆层）
    entries/                     # 主格式 Markdown 条目
      2026-06-07-某主题.md
    items/                       # 遗留 JSON + quote 收藏
      fact/
      preference/
      project/
      relationship/
      quote/
    docs/
      my-article-slug/
        meta.json
        chunk-001.md
        chunk-002.md

groups/{group-id}/memory/        # 群聊记忆，结构同上
```

### 双写关系

```text
写入：extractor/collect → 写文件到 entries/ 或 items/ 或 docs/
                      → indexer 同步到 index.sqlite

读取给 AI：search_memory() 只查 index.sqlite
         → 返回 top-k 片段注入 system
         → related 字段可拉取关联条目
         → 不 os.walk 整个 memory/

人工：可直接打开 entries/ 或 items/ 查看、删改
     → 下次发消息前 indexer 增量 reindex
```

## 4. 条目文件格式

### entries/（主格式）

`memory/entries/2026-06-07-项目进展.md`：

```markdown
---
type: project
importance: 4
keywords: [MeClaw, 记忆系统]
related: []
created_at: 2026-06-07T14:20:00
---

## 摘要
（3-5 句完整段落）

## 要点
- 要点 1
- 要点 2

## 关键词
标签1, 标签2
```

压缩提取时 LLM 优先输出此格式；`extractor.apply_entry()` 写入并更新 `memory.md` 索引行。

### items/（遗留 JSON）

`memory/items/preference/20260604_abc123.json` 仍可读可索引，新压缩默认走 `entries/`。`quote` 收藏仍写 `items/quote/`。

### docs/

长文 `memory/docs/{slug}/meta.json` + `chunk-*.md`，意图命中时按 chunk 检索。

## 5. 发消息链路

挂载点：`backend/api.py` → `build_messages_for_api()`

```text
用户输入
    ↓
calc_context_usage() → 计算 memory 预算
    ↓
intent.py → 是否查长文 chunk（档位 C）？
    ↓
search_memory(query) → 查 index.sqlite FTS，非扫目录
    ↓
组装 messages：
  1. system（soul + memory.md + knowledge…）   ← memory.md 层 1
  2. system（## 相关记忆 …）                   ← 检索结果，可关闭
  3. system（会话摘要）
  4. 编程模式文件上下文
  5. 对话历史
    ↓
流式 API（不变）
    ↓
只存 history；此步不写记忆
```

### 检索分档

| 档位 | 内容 | 何时 |
|------|------|------|
| A | `memory.md`（启动已加载） | 始终 |
| B | `entries/` + `items/` 索引 top-k | 检索开 |
| C | `docs/` chunk 索引 | 意图命中（`intent.py`） |

默认 `memory_token_budget`：1200（估算 token）。

## 6. 压缩上下文：双管线 + memory.md 维护

挂载点：`backend/main.py` → `compress_context()`

```text
用户点击「压缩上下文」
    │
    ├─ job1: conversation_summary
    │         → current_summary（给当前对话接着聊）
    │         → 可选写入 history/summaries/{id}_summary.md
    │
    └─ job2: memory_extraction（memory_enabled 且 memory_write_enabled）
              → AI 输出 Markdown entry（优先）或遗留 JSON
              → 写 memory/entries/{date}-{slug}.md
              → indexer 更新 index.sqlite
              → 追加 memory.md 索引行（链接到 entries/）
```

`memory.md` 索引行示例：

```markdown
- 2026-06-07 [项目进展](entries/2026-06-07-项目进展.md) — MeClaw 记忆系统已切换为 Markdown 条目…
```

**memory.md 三种维护方式**：

| 方式 | 说明 |
|------|------|
| 自动 | 压缩时 extractor 追加索引行（主路径） |
| 手动 | 用户直接编辑文件 |
| AI | `write_memory_file` / `file:edit`（保留） |

## 7. 配置

```json
{
  "memory_enabled": true,
  "memory_retrieval_enabled": true,
  "memory_write_enabled": true,
  "memory_auto_extract": false,
  "memory_token_budget": 1200,
  "memory_extract_threshold_pct": 85,
  "compress_summary_detail": "standard",
  "memory_organizer_enabled": false,
  "memory_organizer_profile_id": "",
  "memory_organizer_bot_id": ""
}
```

| 字段 | 含义 |
|------|------|
| `memory_enabled` | 总开关 |
| `memory_retrieval_enabled` | false = 只检索不写 |
| `memory_write_enabled` | 压缩时是否写记忆 |
| `memory_token_budget` | 每轮检索注入上限 |
| `compress_summary_detail` | 压缩摘要详细度：`brief` / `standard` / `detailed` |
| `memory_organizer_*` | 可选独立 Bot 做记忆整理 |

## 8. 模块结构

```text
backend/memory/
  store.py       # 写 entries/items/docs 文件
  indexer.py     # 文件 ↔ index.sqlite，FTS，reindex
  retrieval.py   # search_memory()，related 扩展
  extractor.py   # 压缩提取，entries 优先，兼容 items
  intent.py      # 长文意图关键词规则
  config.py      # 读取 config 记忆字段
  compress_prompts.py
```

前端：`web/js/memory.js` — 状态面板浏览/删除 entries、items、docs。

---

## 9. 测试要点

1. `memory/entries/` 有文件，但 prompt 里只有检索到的几条
2. 压缩后 `entries/` 新增 + `memory.md` 多了一行索引
3. Bot A 的 `memory/` Bot B 读不到；群记忆在 `groups/{id}/memory/`
4. 手删某个 entry 后 reindex，检索不再命中
5. 普通问答不带长文 chunk；问「按上次风格写」才触发 docs 检索
